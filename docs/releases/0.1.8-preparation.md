## Necessary release fix included in this preparation

The source reactor contains `measurement-core`, added by merged PR #142, but
both workflows still staged and allowed only the root, backend and optics POMs.
As a result, a local version change could be tested with an uncommitted
measurement POM while the immutable publication candidate retained its old
parent version. A complete version-only commit was also rejected by both
file-list guards.

The preparation adds `measurement-core/pom.xml` to the two staging commands
and the two exact metadata allowlists. It preserves the version-only boundary,
expected-SHA checks, required tests and protected publication. Recovery
instructions now describe four POMs and the actual repository-derived inputs.

The new test uses disposable local Git repositories and the actual workflow
staging commands and diff guards. It is part of the existing Maven-owned
`SupplyChainConfigurationTest`. It checks complete release and next-SNAPSHOT
commits, accepts all reactor version metadata and rejects unrelated files.

After the reviewed fix and preparation are on authoritative `main`, use
**Release** (`.github/workflows/deploy-release.yml`) from `main` with:

| Input | Value |
|---|---|
| `next_development_version` | `0.1.9-SNAPSHOT` |
| `next_version_increment` | `patch` |
| `dry_run` | **`true`** |

The orchestrator rejects dispatch from a preparation branch and rejects a moved
main. It derives the release version from the POM and `release.properties`,
creates the local version-only candidate and executes `mvn -B -ntp verify`
with tests. A successful dry run publishes no candidate branch, tag, release,
attestation, container or package.

This preparation has not dispatched or passed that rehearsal. The recorded
main is a source baseline, not the final release SHA. Refresh it after the PR
is merged; the release workflow must derive its own exact starting and
candidate SHAs.

[release recovery guide](../release-recovery.md). Its repository-side reviewer
and ref restrictions cannot be proven from the workflow file alone and were

JAR, checksums, provenance, archive smoke test and platform installer results
